QQ 农场助手的 **群晖 Synology DSM 原生套件（`.spk`）** 版本。

> [!IMPORTANT]
> **本仓库的群晖适配 100% 由 AI 完成，零人工编码。**
> `synology/` 打包链、DSM 生命周期钩子、前端群晖化改动、本 README 与 `docs/` 下的文档，全部由 AI 编写并在真实群晖（SA6400 / DSM 7.2.2）上安装、运行、原地升级验证过。文中每一条「实测」都对应一次真实执行与取证，不是推断或复制粘贴。人只负责两件事：提需求、拍板。

## 群晖版是什么样的

- **DSM 原生套件**，不是 Docker。由套件中心统一安装、启停、升级（`INFO` 里 `ctl_stop="yes"`，重装/升级会走钩子）。开机自启走 DSM 标准链路：套件中心会为本包生成 `pkgctl-qq-farm-bot.service`（实测 `enabled`，`WantedBy=syno-low-priority-packages.target`，`ExecStart` 调 `synopkgctl start`，与手动启动是同一个 `start-stop-status`）；这条链在机上取证过，但没做过真机重启验证。
- **自带 Node.js 22 官方二进制**，不依赖套件中心的「Node.js」套件；后端是 esbuild 打出的两个纯 JS 文件（`bin/main.js`、`bin/worker.js`）。
- **以普通包账号运行**：`conf/privilege` 只声明 `defaults.run-as="package"` + `username`/`groupname = sc-qq-farm-bot`，不声明任何 root 权限。DSM 7.2 会**直接拒绝**声明 root 的第三方包，连解包都不做——这是装机实测踩到的第一道墙，别照着官方套件文档加 `ctrl-script`。
- **监听 TCP，默认放行局域网**：`0.0.0.0:3007`，浏览器直接开 `http://<群晖 IP>:3007/`。不走 `/webman/3rdparty/` 网关前缀（那个前缀只伺服静态文件，不是反向代理）。
- **移除了登录 / 改密模块**：应用内没有管理员账号密码，谁能连上这个端口谁就是管理员。

## ⚠️ 装完先看这段

默认监听 `0.0.0.0:3007` 意味着**同网段任何设备打开这个端口就能控制你挂在上面的 QQ 账号**（应用没有登录页，也没有二次校验）。确认内网可信再用；想收紧改 `/var/packages/qq-farm-bot/var/settings.conf`（这个路径与套件装在哪个卷无关，`var` 是 DSM 建的软链，本机指向 `/volume1/@appdata/qq-farm-bot`，装在其他卷就指向对应卷）：

```ini
ADMIN_HOST="127.0.0.1"   # 只本机可达，之后靠 SSH 端口转发或反代/隧道访问
ADMIN_PORT="3007"
LOG_LEVEL="info"         # error / warn / info / debug
```

改完在套件中心重启套件生效（`settings.conf` 由 `scripts/start-stop-status` 每次启动时 source）。如果要出公网，务必把 `ADMIN_HOST` 改回 `127.0.0.1`，认证放在反代/隧道那一层，并清掉转发过来的 `X-Trim-*` 请求头——**没有这些头时应用把访问者当作管理员**，客户端自己伪造 `X-Trim-Isadmin: false` 反而会把自己挡在门外。不要把 3007 端口直接映射到公网。

`postinst` 只在 `settings.conf` **不存在时**才写默认值，所以升级不会覆盖你改过的配置。升级过程中 DSM 会依次跑 `stop → preupgrade → preuninst → postuninst → preinst → postinst → postupgrade → start`（`-4 → -5 → -6` 两次原地升级实测，八步全 `code:0`，`settings.conf` 与 `data/` 的 md5 前后一致）——注意**卸载钩子在升级里也会被执行**，`postuninst` 删数据等于升级时清库。

## 安装

1. 取 `qq-farm-bot_<版本>_<架构>.spk`（当前本仓库 Releases 还没发布产物，按下节自行构建；发布后一律核对同目录的 `.sha256`）。版本号是构建日期 `YYYY.MM.DD-N`，例如 `2026.11.02-4`——DSM 把它当「主版本-feature build」两段比较，同一天再出一版就把 `-N` 递增，套件中心能直接覆盖升级。
2. 套件中心 → 「手动安装」，选择该 `.spk`，按向导点到底（第三方包没有 Synology 签名，向导里的来源确认文案随 DSM 小版本变化，本机 7.2.2-72806 上正常走完，安装期日志落在 `/var/log/synopkg.log`）。
3. 安装完自动启动。浏览器打开 `http://<群晖 IP>:3007/` 就是管理面板。

**扫码登录要自己接原始项目那套前置**：本套件只把后端和面板跑起来，不含 QQ 登录服务。面板「设置 → 系统设置 → 登录设置」里 `QQ扫码登录` 默认关闭，`NapCat接口地址` / `NapCat接口签名` 留空时保存就报「开启 QQ 扫码登录前，请配置 NapCat 接口地址和接口签名」。要先自行部署 `qq-miniapp-auth` 服务，怎么部署、两项怎么填看原始项目的说明（飞牛版那层文档里也没这段），参考链接：<https://github.com/liyangpengs/qq-farm-bot>。本仓库不重复、也不提供任何登录服务。

架构选 `x86_64`（含 SA/DS 的 Intel-AMD 机型）或 `armv8`（rtd1296 / rtd1619 / armada37xx）。**装前确认 glibc**：Node 22 需要 ≥ 2.28，在群晖上跑 `echo x | /lib/libc.so.6 | head -1`（DSM 的 `/usr/bin/ldd --version` 没有任何输出，别看它）。`x86_64` 包已在 DSM 7.2.2-72806 Update 8 + SA6400（glibc 2.36）实机装成功并跑起任务；`armv8` 只是打包链参数化，尚未实机验证。

卸载：`/var/packages/qq-farm-bot/var/`（数据目录，本机即 `/volume1/@appdata/qq-farm-bot`）里的账号、登录态和日志**实测在卸载后仍然保留**（连装带卸三个版本来回，`data/logs/` 里最早的日志还在）。但套件中心的卸载弹窗若勾选了删除套件数据则会清空，动手前自己备份这个目录。

**重启要重新扫码**：套件每次重启——覆盖升级、改 `settings.conf` 后重启、重启 NAS——之后，已保存的 QQ 登录 Code 都连不上（网关在 WebSocket 握手阶段直接回 400，实测 13 分钟后重试依旧），必须在面板里逐个账号重新扫码。应用没有自动刷新 Code 的能力，日志里「等待 Helper 刷新 Code」那句只是文案。所以别在挂机时段升级。

## 自行构建

**只能在 Linux 上构建**（`.spk` 外层是不压缩的 tar，内含带可执行位的 `node`；在 Windows/Git Bash 打包会丢权限，装到 DSM 上起不来）。依赖：GNU tar、Node.js 20+、pnpm 10、curl。

```sh
pnpm install
synology/build.sh                              # x86_64，版本号取当天日期 -1
SPK_ARCH=armv8 synology/build.sh               # armv8
SPK_VERSION=2026.11.2-3 synology/build.sh      # 指定版本号
```

产物在 `synology/out/qq-farm-bot_<版本>_<架构>.spk`（+ `.sha256`）。可覆盖的环境变量：`SPK_ARCH`、`SPK_VERSION`、`NODE_VERSION`、`NODE_CACHE_DIR`（复用已下载的 Node dist，跳过外网拉取）、`SKIP_INSTALL=1`（依赖已装好时跳过 `pnpm install`）、`MAINTAINER`（写进 `INFO` 的发布商名，仓库没有 git 配置时会是 `unknown`）。

构建脚本里两个不显然的约束：不得把 `QQ_FARM_NO_TCP=1` 编进产物（脚本会 grep 拦住，否则群晖版永远拒绝监听 TCP）；后端依赖必须全是纯 JS，出现 `.node` 原生模块就得随包提供对应架构的预编译文件（同样会拦）。

完整教程——怎么在群晖本机搭构建用的 Node/pnpm、DSM 没有 sftp 时怎么传代码、出包后不装就能验完的自检清单、失败对照表——见 [`docs/synology-build.md`](docs/synology-build.md)。

## 运行期位置

| 路径 | 内容 |
|---|---|
| `/var/packages/qq-farm-bot/` | `INFO`、`conf/privilege`、`scripts/`（DSM 用的钩子） |
| `/var/packages/qq-farm-bot/target` → `/volume1/@appstore/qq-farm-bot` | `node/bin/node`、`server/bin/*.js`、`server/resources/`、`server/web/dist` |
| `/var/packages/qq-farm-bot/var` → `/volume1/@appdata/qq-farm-bot` | `settings.conf`、`data/`（账号、登录态、日志）、`qq-farm-bot.log`、`qq-farm-bot.pid` |

排查命令用绝对路径：非交互 SSH 里 `synopkg` 不在 PATH 上，得写 `/usr/syno/bin/synopkg status qq-farm-bot`。

## 额外功能

以下功能由飞牛版 fork 新增，群晖版一并带上。设置类功能**按账号分别设置，默认关闭**。

「设置 → 大小号协作」：

- **大号/小号**：把账号设为小号并从好友中选择大号后，可打开「成熟作物先留给大号偷」（默认开）：小号的成熟作物先留给大号偷，检测到大号偷过才自动收获，可设置超时后仍收获；关掉则小号正常收获自己的地。手动收获不受限制。
- **不偷大号的菜**：小号自动巡查好友时不偷大号。
- **只给大号放捣乱**：小号的放草、放虫只对大号做，不对其他好友做（「自动捣乱」关着也会对大号放）；帮大号时有草/虫的地不帮，留给大号自己清。
- **偷收比**：生涯偷菜 ÷ 生涯收获 × 100%（与好友卡片「收偷比」同一组数据）。阈值默认 80%，超过才触发。可单独打开：拒绝高偷收比好友申请、好友页按偷收比筛选、高偷收比好友来偷菜时用现有 Bark 推送、自动删除高偷收比好友（大小号协作里的大号和小号不删）。四项默认关。
- **在线期间来偷菜的自动删除**（默认关，与偷收比阈值无关）：程序正在运行且这次上线之后，有好友来偷菜就删除。掉线、程序停止，以及重连后补拉到的历史记录不删。不删大号、本机登录过的小号，也不删奶茶「优先雇佣人」。两次删除至少间隔 1 分钟。

「设置 → 活动设置」：

- **奶茶活动自动雇佣**：员工位空出时自动雇佣好友，任何账号都可开启，不依赖大小号设置。可从好友里按顺序指定多个「优先雇佣人」（可搜索添加、拖动或上下按钮调整顺序）：有空位时按顺序先雇当前空闲的优先雇佣人，他们都不空闲或没指定时随机雇其他好友。雇佣时长统一一个设置（4/12/24 小时或随机），雇谁都按它；职业可选或随机。旧版小号开了自动雇佣的，升级后默认把大号当作优先雇佣人，时长沿用原来的「雇佣时长」。约每 10 分钟检查一次，员工下班后约 1 分钟内补雇。会消耗奶茶券。
- **被雇佣后自动做工作事项**：本账号被别人雇佣时，每个兼职班次自动为老板做一次工作事项（约每 10 分钟检查一次），可指定或随机（随机只在宣传推广、花式摇杯、招牌试饮中选）。需要在被雇佣的账号上打开，例如 A 号雇了 B 号，就在 B 号上打开。
- **奶茶收益自动领取**：每小时领取一次奶茶店收益。
- **森野种子自动兑换**：每天在奶茶活动兑换商店兑换勾选的森野种子（芭乐、黄金芽、柿子、可可豆、红柚、甜橙、白桃、甜莓，可拖动排序），每种按最大数量（受剩余限购、当前货币和持有上限限制），货币不够时按顺序兑换；已兑换、售罄或货币不足时当天跳过。会消耗兑换货币。
- **自动制作奶茶**：约每 10 分钟把背包里可做奶茶的森野果实（只限店铺已解锁的配方，锁定的果实不动）做成奶茶；可选「也制作金露云酪」，不选时森野黄金芽保留不做，只做其他奶茶。结算期不制作。
- **自动领取工资**：本账号被别人雇佣打工后，约每 10 分钟检查一次，有可领的工资就领取（需本账号奶茶店已开业）。
- **店铺自动升级**：自己的奶茶店营业额达到下一级要求时自动升级并领取升级奖励（约每 10 分钟检查，条件不够时 30 分钟后再看），需本账号奶茶店已开业。
- **图鉴奖励自动领取**：约每 10 分钟检查作物图鉴、变异图鉴，有可领的等级奖励就领取。
- **自动完成图鉴**：找出作物图鉴里未收藏、背包里没有种子、地里也没种着的作物，从种子商店买 1 个种子（只买已解锁、等级够、不需要解锁卡、未售罄且金币够的；每次检查最多买 1 个，同时最多 2 个待种，同一种子最多自动买 3 次），下次自动播种时先把它种下，种下或收藏后恢复原来的播种顺序。会花金币，需要打开自动种植。

「设置 → 策略设置」：

- **背包种子优先顺序：改序号、拖动排序**：每行左边的序号可以点一下直接改，输入目标位置后回车或点别处即移过去，其他种子依次顺延（超出范围按第 1 位或最后一位算，输错了恢复原序号）；也可以按住序号右侧、上下箭头左边的拖动手柄（六个点）拖到想要的位置，拖动时有插入位置提示线和「移到第 N 位」气泡，拖到列表上下边缘会自动滚动。手机上只有按住手柄才拖动，其他地方照常滑动页面。原来的上/下箭头仍保留。

「设置 → 系统设置 → 下线提醒」（全局设置）：

- **Bark 静音也提醒（重要警告）**：推送渠道选 Bark 时出现此开关，默认开启。开启后账号掉线的提醒以 Bark「重要警告」发送（音量 5、铃声持续约 30 秒），手机静音或勿扰时也会响铃，「测试通知」同样按此设置发送；其他事件提醒仍为普通推送。需在 iPhone「设置 → 通知 → Bark」里允许「重要警告」。同时修复了 Bark（以及 PushPlus、WxPusher）推送成功却提示「测试失败: success」的问题。

「概览 → 运行日志」：

- **偷菜日志 / 报错日志分栏**：运行日志分为「全部」「偷菜日志」「报错日志」三栏，原来的过滤器照常可用。偷菜日志收录偷到菜的好友访问、巡查总结、小号给大号留菜的记录。报错日志收录错误和警告，可选只看错误或只看警告。偷菜、报错两类日志各自最多保留最近 1000 条，不会被普通日志挤掉。

「我的农场」：

- **地块卡片直接施肥**：每块地的卡片上有「普通肥」「有机肥」按钮，点一下只给这一块地施肥；当前不能施肥时按钮变灰，悬停可看原因（如「当前作物无需施肥」「有机化肥次数已用完」）。受「设置 → 自动控制 → 显示手动施肥按钮」控制，进入「选择土地」时隐藏。上游的选地批量施肥和一键施肥照常可用。

「页头」：

- **游戏公告（只读）**：页头的公告图标可查看当前账号的游戏公告标题列表，点开看全文、起止时间和封面图。只读取，不会替你标记已读；账号需已启动并登录。
- **界面固定浅色**：去掉深色模式和主题切换，界面始终为浅色。概览页「运行日志」卡片的底边与「今日统计」对齐，日志多时在卡片内滚动。

执行结果会写在日志里。这些功能的来源与逐版变更见上游的 [`fnos/飞牛部署与变更说明.md`](fnos/飞牛部署与变更说明.md) 中 2026.10.20.1、2026.10.21、2026.10.21.1、2026.10.21.2、2026.10.21.3、2026.10.21.4、2026.10.22、2026.10.22.1、2026.10.27、2026.10.27.1、2026.10.29、2026.10.29.1、2026.10.30、2026.10.31、2026.11.1、2026.11.2、2026.11.2.1 和 2026.11.2.2 各节。
